十亿AI Agent把数据库变成高危现场

The MAD Podcast with Matt Turck

What Happens When Billions of AI Agents Hit Your Database? (Andy Pavlo)

Andy Pavlo 加入 ClickHouse 创办 ClickHouse Labs，说明数据库厂商抢的是 agent 时代的数据库入口，不是多一个向量索引。数据库与 AI 的交集已经不在 RAG 和向量检索，而在 agent 直接建库、写入、改表，甚至误删生产库；你如果还把 AI 数据库等同于“上一套向量库”，架构和采购重点就会放错。

向量数据库早在 2016 年就存在，ChatGPT 之后才因 RAG 和聊天机器人变得有用。但它的核心只是一个索引，护城河不深，一年内主流数据库几乎都补上了向量索引，vector search 已经变成 table stakes；你仍然该用向量检索增强 agent，但没必要为这个功能单独引入一套只能做向量搜索的数据库，先看现有数据库能不能覆盖需求。

更实际的变化是 agent 开始创建数据库分支。Neon、Databricks 相关数据里，agent 创建分支的占比已经高到不能当边角料看；branching 的价值是给 agent 一份生产库的 copy-on-write 快照，让它在真实数据形态上改 schema、跑测试、写功能，验证完再合回生产库，避免过去用 staging 小样本测完、上生产才发现问题。

风险也要按生产变更来管：每月都有人因为 agent 删了东西而丢生产库，Andy 把这形容成“给猎豹喂可卡因再塞进法拉利”。别让 agent 直接拿生产库写权限；用分支、权限隔离、审计和可回滚快照，把 agent 的试验区和系统记录隔开。
