持续学习产品化：Trajectory押注模型闭环

Training Data

A Model For Everyone: How Ronak From Trajectory Is Building Products For Continual Learning

Ronak把Apple式整合逻辑搬到模型生命周期：训练、评估、部署放在同一处，生产流量再回流成新数据，闭环跑起来。对企业来说，别再分别拼训练平台、评测工具和部署服务；一套系统要把“想要的效果”直接变成模型更新。Trajectory先让非研究团队也能定制模型，这一步像MapQuest：仍离线，但不再依赖AAA式的人工地图服务。终点是Google Maps式持续学习：每次使用都更新路线，模型从真实使用中聚合最优解。

今天的“持续学习”多数是伪持续学习。人脑在线更新，当前agents定制一次后常靠批量更新。Ronak不认为必须等架构大突破：DeepSeek等模型已在改基础结构，比如fast/slow memory和跨层skip connections；但架构只解决一半。企业知道自己要什么效果，最难的是把“好”翻译成训练信号和评测标准，Trajectory要补的就是这层产品化中间层。

过去从数据到智能只在实验室：Windsurf训练模型要大规模研究团队、数亿美元算力和六到九个月，Cursor Composer同理。这个成本决定大多数公司不能自建。产品机会在封装重复流程：企业只调关键knobs and levers，其余由系统处理。你不是AI公司，买这种闭环比招研究团队更现实；你是AI产品公司，界面要暴露业务指标而不是训练细节。

三位创始人的经验指向同一问题。Ronak在Windsurf从生产编辑和retries里学；Michael在DeepMind的Gemini Robotics让机器人按天更新；Arjun在Apple Vision Pro把艺术家反馈用于多模态基础模型。他们看到的不是单点工具，而是grand alignment problem：把真实世界反馈持续转成模型改进。Trajectory押注持续学习成为下一学习范式；判断标准很简单，模型是否因真实使用每天变好，而不是靠季度性大版本更新。
