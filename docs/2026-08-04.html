AGI自动化实验室：先理解旧架构的边界

Training Data

Building the Automated AGI Lab: Core Automation's Jerry Tworek and Rohan Anil

本期 Training Data 请来 Core Automation 两位创始人 Jerry Tworek 和 Rohan Anil。Jerry 曾是 OpenAI VP，负责 strawberry 和 reasoning 团队；Rohan 曾是 Gemini 预训练四位负责人之一，也在 Google Brain 和 Anthropic 做过核心研究。两人从实验室走到创业公司，想做的不是再堆一个更大的模型，而是把 AGI 从研究项目变成能自动干活的系统。Jerry 用一条 tweet 开场：要替换 Transformer，第一步是真正搞懂它把我们带到了多远。

这句话不是给 Transformer 写悼词。Jerry 的意思是，大多数人优化 Transformer 时只想着怎么把它变便宜、变高效，却很少想怎么让它更有表达力、更强大。过去六年，AI 界实际上只驯服了两个算法：大规模预训练和大规模强化学习。模型越训越大，参数越加越多，但底层操作还是 MoE 和 attention。现在真正的瓶颈不是算力，不是数据，而是架构本身。这个判断对任何做 AI 基础设施的人都有用：如果下一轮突破来自新架构，那么今天围绕 Transformer 做的很多优化可能都会被推翻。

Jerry 的反思来自他在 OpenAI 的亲身经历。他曾是强化学习的坚定信徒，认为只要把 RL 规模做大，2025 年就能解决所有问题。结果是模型在 benchmark 上分数持续上涨，真实世界的任务却依然做不完。问题出在训练分布和真实分布是两回事：实验室里的评估和训练数据本质上是同一套东西，而现实世界的任务更乱、更模糊、更难定义。Jerry 说模型训练者的常见抱怨是“没有足够难的任务”，这恰恰说明现在缺的不是更强的算力，而是更接近真实工作的训练目标。

Core Automation 的名字就是答案：把任务自动化。Jerry 说他现在用 Codex 写代码、跑工作流，但仍然要自己坐在工位上，仍然要告诉它做什么，仍然要检查它做没做对。这个“为什么还没有全部自动化”的落差，就是 Core Automation 要补上的研究空白。如果你在评估 AI 产品能做到什么程度，这段对话能帮你理解：下一代模型不一定更快，但一定更擅长把真实任务拆解并执行到结果。
